# ADR-013: TLAS 4D Relationship Matrix and Dynamic Overrides Architecture

**หมายเลขเอกสาร:** ADR-013
**หัวข้อ:** การใช้สถาปัตยกรรม Rule-Based Taxonomy, ตรรกะ 3-Tier Fallback และความสัมพันธ์แบบ 4 มิติ (4D Relationship Matrix) สำหรับระบบแปลบทสนทนา
**สถานะ:** อนุมัติ (Accepted)
**วันที่:** 2026-08-03
**ผู้รับผิดชอบ:** ATF Core Team

---

## 1. บริบทและปัญหา (Context & Problem Statement)

ในการแปลโปรเจกต์เกม RPGM/Ren'Py ขนาดใหญ่ที่มีสคริปต์ซับซ้อน ความท้าทายสูงสุดคือการรักษาความคงที่ของ "สไตล์ภาษาและสรรพนาม" ของตัวละคร โดยมีข้อจำกัดและปัญหาเชิงโครงสร้างดังนี้:

* **ความสัมพันธ์ที่ทับซ้อนและขัดแย้ง:** การระบุความสัมพันธ์แบบมิติเดียว (เช่น `REL_SPOUSE` หรือ `REL_FRIEND`) ไม่สามารถรองรับความสัมพันธ์ที่ซับซ้อนได้ (เช่น คู่แต่งงานที่เกลียดชังกัน, เจ้านายที่แอบรัก, หรือบอสมาเฟียที่ทำตัวขี้เล่นคุกคาม)
* **การแทรกแซงทางอารมณ์ (Dynamic Context):** ตัวละครที่เป็นคนสุภาพเรียบร้อย (Base Profile) อาจจำเป็นต้องหลุดสบถหรือเปลี่ยนสรรพนามเมื่ออยู่ในสภาวะโกรธจัด คลั่งรัก หรือเผชิญหน้ากับศัตรู
* **ข้อจำกัดเรื่อง Token Size:** การขยาย Taxonomy เพื่อใส่เงื่อนไขความสัมพันธ์เฉพาะเจาะจงทุกรูปแบบ จะทำให้ฐานข้อมูลใหญ่เกินไป ซึ่งเป็นอุปสรรคต่อการนำไปประมวลผลผ่าน AI (LLM) และทำให้การสกัดข้อมูล (Data Extraction) ทำได้ยาก
* **การทำงานกับ Raw Data:** สคริปต์เกมประกอบด้วยแท็กคำสั่ง (Control Codes) และข้อมูลผู้พูดที่ปะปนกันอยู่ ซึ่งไม่พร้อมสำหรับการนำไปประมวลผลทันที

## 2. การตัดสินใจ (Decision)

ออกแบบสถาปัตยกรรมระบบเป็น Data-Driven Processing Pipeline โดยมีข้อกำหนดดังนี้:

### 2.1 โครงสร้างความสัมพันธ์แบบ 4 มิติ (4D Relationship Matrix)
แยกมิติความสัมพันธ์ของตัวละครในฟิลด์ `relationships` ออกเป็น 4 แกน เพื่อให้รองรับสถานะทางจิตวิทยาที่ขัดแย้งกันได้:

1. **`roles` (Structural Social Roles):** หน้าที่ของบทบาทเชิงโครงสร้างสังคม (ยุบรวมตำแหน่งที่มีพลวัตอำนาจเหมือนกัน เช่น กษัตริย์/บอสมาเฟีย รวมเป็น `ROLE_AUTH_MASTER` เพื่อประหยัด Token)
2. **`affinity` (Affinity & Feelings):** ความรู้สึกภายใน (เช่น รักมาก, ชอบพอ, แอบรัก, ย้อนแย้ง, ระแวง, เกลียดชัง, หวังเคลม, คลั่งรัก)
3. **`intimacy` (Intimacy Level):** ระยะห่างและความสนิทสนม (รู้ใจ, คุ้นเคย, ห่างเหิน, ตัดขาด)
4. **`power_dynamic` (Power Dynamic):** อำนาจต่อรองเมื่ออยู่ด้วยกัน (เป็นผู้นำ/คุมเกม, เท่าเทียม, ยอมจำนน)
5. **`specific_speech` (Target Specific Speech):** สรรพนามเฉพาะเมื่อคุยกับตัวละครนี้โดยเฉพาะ

### 2.2 ตรรกะการตัดสินใจแบบลำดับชั้น พร้อมการแทรกแซงทางอารมณ์ (Priority Resolution Engine)
ระบบจะเลือกสรรพนามและหางเสียงตามลำดับความสำคัญ (Priority) ดังนี้:

* **Tier 0: Dynamic Context Override (เงื่อนไขแทรกแซงสูงสุด):** หากประโยคมีแท็กอารมณ์/สถานการณ์รุนแรง (เช่น `EMO_ANGER`, `TON_AGGRESSIVE`, `EMO_AROUSED`, `TON_SEDUCTIVE`) ระบบจะวิ่งไปเช็คกฎ Dynamic ใน Taxonomy ที่มีคะแนนสูงสุด (Score 90+) เพื่อทับซ้อน (Override) สรรพนามปกติทันที (เช่น เปลี่ยนจาก "ผม" เป็น "กู" หรือสั่งตัดคำลงท้าย "ครับ" ทิ้ง)
* **Tier 1: Exact Match:** ตรวจสอบ Listener ID กับ `relationships` ใน Profile หากตรงกัน ให้ประเมินคะแนนจาก 4D Matrix หากผ่านเกณฑ์ ให้ใช้ `specific_speech` หรือกฎความสัมพันธ์เฉพาะ
* **Tier 2: Target Condition Match:** หากเป็นคนแปลกหน้า หรือ NPC ให้ดึงลักษณะผู้ฟัง (เช่น เพศ, อายุ, บทบาททางสังคม) ไปเทียบกับ `target_conditions` ใน Taxonomy
* **Tier 3: Base Profile Fallback:** หากไม่เข้าเงื่อนไขใดเลย ให้ใช้ `base_speech_style`

### 2.3 การประมวลผลไวยากรณ์ไทย (Thai Grammar Processing)
กำหนดให้ระบบคายผลลัพธ์เป็น Root Word (เช่น "คะ/ค่ะ", "ครับ") ส่วนการประกอบรูปประโยคที่ถูกต้อง (เช่น นะคะ, ไหมคะ) หรือการลากเสียง (เช่น คร้าบ, ค่าา) ให้อิงจากประเภทของประโยค (บอกเล่า/คำถาม) และแท็กอารมณ์ประกอบกัน

### 2.4 ท่อส่งข้อมูลและการสกัดข้อมูล (Data Extraction Pipeline)
ก่อนเข้าสู่ระบบประมวลผล ข้อมูลดิบต้องถูกกวาดและทำความสะอาดแบบ Line-by-line โดยใช้ Regular Expression (Regex) เพื่อแยก `Speaker_ID` และทำ Masking ซ่อน Control Codes ของเอนจิ้นเกม (เช่น `\|`, `\fb`) ไว้ชั่วคราว เพื่อป้องกันความเสียหายของโค้ด

## 3. ผลที่ตามมา (Consequences)

* **ความยืดหยุ่นสูง (High Flexibility):** ระบบครอบคลุมทุกแนวเกม (Universal) และสามารถปรับเปลี่ยนสไตล์การพูดของตัวละครได้สอดคล้องกับอารมณ์จริงในบรรทัดนั้นๆ โดยไม่กระทบกับนิสัยตั้งต้น
* **ปรับแต่งประสิทธิภาพ (Token Optimization):** Taxonomy ถูกบีบอัดให้อยู่ในเชิงโครงสร้างนามธรรม ทำให้ขนาดไฟล์เล็กลง ประมวลผลผ่านสคริปต์ได้รวดเร็วและแม่นยำ
* **การพึ่งพามนุษย์ (Human-in-the-loop):** แม้ระบบจะสามารถคาย "ไกด์ไลน์ตั้งต้น" ที่ถูก Override ตามอารมณ์ได้แล้ว แต่นักแปลยังต้องเป็นผู้ตัดสินใจขั้นสุดท้ายในการเลือกใช้รูปประโยคไวยากรณ์ไทยให้สละสลวยและเข้ากับรูปปาก/จังหวะของเกมที่สุด
