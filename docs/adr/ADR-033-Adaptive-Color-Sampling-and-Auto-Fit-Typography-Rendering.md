# ADR-033: Adaptive Color Sampling, Clean Inpainting Margin, and Auto-Fit Typography Rendering Architecture

## Status
Accepted / Implemented

## Context & Problem Statement (บริบทและปัญหา)

เมื่อทำการทดสอบเรนเดอร์ข้อความภาษาไทยลงบนรูปภาพเกมจริง (`python localize_images.py render`) พบข้อบกพร่องทางสถาปัตยกรรม 3 ประการหลักที่ทำให้ผลลัพธ์ไม่สามารถนำไปใช้งานจริงได้:

1. **Stark White Box Artifact (กล่องสี่เหลี่ยมสีขาวแปะทับภาพมั่ว):**
   - ในระบบแคตตาล็อกเดิม ค่าเริ่มต้นของสีถูกกำหนดเป็น `Bg_Color="#FFFFFF"` และ `Text_Color="#000000"` เสมอ
   - เมื่อภาพเกมต้นฉบับมีพื้นหลังเป็นสีดำสนิท (เช่น หน้าจอสอนเล่น `Fishguide.png`, `BeachBarTutorial.png`, หรือหน้าต่าง UI มืด) ตัวเรนเดอร์เดิมจะเทสีสี่เหลี่ยมขาวทึบลงไปทับภาพ ทำให้ผลลัพธ์ดูเหมือนเอาสติ๊กเกอร์สีขาวมาแปะกล่องทับดื้อๆ ขาดความกลมกลืนกับงานศิลป์ของเกมอย่างสิ้นเชิง

2. **Bounding Box Misalignment & English Letter Leaks (เศษตัวหนังสือภาษาอังกฤษเดิมตกค้าง):**
   - ตัวเรนเดอร์เดิมมีการบีบขอบเขตการลบให้เล็กลงจากกรอบจริง: `draw.rectangle([x + 6, y + 6, x + w - 4, y + h - 4])` (หดขอบเข้ามา 6px ด้านบน/ซ้าย และ 4px ด้านล่าง/ขวา) ส่งผลให้ขอบและหางของตัวอักษรภาษาอังกฤษเดิม (เช่น `g`, `y`, `d`, `b`, จุด `..`) ไม่ถูกลบ และโผล่แลบออกมาให้เห็นรอบขอบกล่อง
   - ตัวจับข้อความ OCR ดั้งเดิมตรวจจับข้อความเฉพาะท่อน เช่น สกัดเฉพาะคำว่า "Prep" โดยตกคำว่า "2." หรือสกัดเริ่มบรรทัดที่ 2 ในกรณีฟอนต์หัวเรื่องตัวใหญ่ ทำให้พิกัดกล่องเดิมไม่คลุมตัวหนังสือจริง 100%
   - ในชุดภาพแชต `MasaruEnding1_Phone` พิกัดเดิมเอียงเยื้องไปทางซ้าย 32 พิกเซล (`X=380, Width=200` แทนที่จะเป็น `X=412, Width=230`) ทำให้กล่องขาวกินเข้าไปในลายวอลเปเปอร์มือถือด้านซ้าย และเหลือเศษตัวอักษรภาษาอังกฤษด้านขวา

3. **Font Overflow & UI Spillover (ฟอนต์ล้นกรอบและทะลักทับ UI อื่น):**
   - ตัวเรนเดอร์เดิมไม่มีการตรวจสอบความสูงของข้อความจริง (No Vertical Constraint Measurement) และบังคับใช้ขนาดฟอนต์คงที่ (เช่น `Font_Size=18`)
   - เมื่อข้อความภาษาไทยมีความยาว (เช่น แชต 150 ตัวอักษรของชิออนใน `ShionMessage1.png`) เมื่อตัดขึ้นบรรทัดใหม่ตามความกว้างกล่องแคบๆ จะกลายเป็น 10-14 บรรทัด ซึ่งมีความสูงรวมกว่า 250 พิกเซล (สูงเกินกล่องเดิมที่มีขนาดเพียง 79 พิกเซล) ส่งผลให้ข้อความภาษาไทยล้นทะลักลงมาทับกล่องแชตอันถัดไปและทับภาพเกมด้านล่างจนอ่านไม่รู้เรื่อง

4. **Automation vs Manual Photoshop Dilemma:**
   - ผู้ใช้เกิดคำถามว่าปัญหาเหล่านี้แก้ไขด้วยระบบสคริปต์ได้หรือไม่ หรือจำเป็นต้องเปิด Photoshop แต่งภาพทีละภาพด้วยมือ ซึ่งหากเกมมีรูปภาพเป็นร้อยๆ รูป การทำด้วย Photoshop จะใช้เวลาเป็นสัปดาห์หรือเป็นเดือน และขัดกับปรัชญาของ ATF

## Architectural Decision (การตัดสินใจเชิงสถาปัตยกรรม)

เราได้ออกแบบและติดตั้ง 4 เสาหลักทางสถาปัตยกรรมเพื่อแก้ปัญหาทั้ง 3 จุดอย่างเบ็ดเสร็จในระดับ Engine:

```
+-------------------------------------------------------------------------------+
|                      ATF IMAGE LOCALIZATION PIPELINE                          |
+-------------------------------------------------------------------------------+
|                                                                               |
|  [Raw Game Image]                                                             |
|         |                                                                     |
|         v                                                                     |
|  +-------------------------------------------------------------------------+  |
|  | 1. Pixel-Level Adaptive Color Sampling (auto_detect_box_colors)         |  |
|  |    - Perimeter Pixel Sampling (สุ่มสีรอบนอกกรอบข้อความ)                 |  |
|  |    - Luminance Contrast Calculation (bg_lum < 115 -> White Text)        |  |
|  |    - Alpha Channel Transparency Handling (avg_a < 30 -> Clear Alpha)   |  |
|  +-------------------------------------------------------------------------+  |
|         |                                                                     |
|         v                                                                     |
|  +-------------------------------------------------------------------------+  |
|  | 2. Zero-Leak Pre-render Cleaning (erase_pad = 3)                        |  |
|  |    - Expanded Inpainting Bounds: [x-3, y-3, x+w+3, y+h+3]               |  |
|  |    - 100% Obliteration of English character fringes and tails          |  |
|  |    - Seamless Inpainting using detected Background Color / Alpha        |  |
|  +-------------------------------------------------------------------------+  |
|         |                                                                     |
|         v                                                                     |
|  +-------------------------------------------------------------------------+  |
|  | 3. Adaptive Dynamic Typography (fit_thai_text_to_box)                   |  |
|  |    - Iterative Font Downscaling (Desired Size -> Min Size)              |  |
|  |    - Dual Constraint Verification: total_text_h <= H & max_line_w <= W  |  |
|  |    - Dynamic Line Spacing & Word Wrapping (PyThaiNLP)                   |  |
|  +-------------------------------------------------------------------------+  |
|         |                                                                     |
|         v                                                                     |
|  +-------------------------------------------------------------------------+  |
|  | 4. High-Fidelity Rendering & Timestamp Decoupling                       |  |
|  |    - Dynamic Stroke/Outline Generation for readability                  |  |
|  |    - Isolated Chat Timestamp Placement (Bottom-Right Anchor)            |  |
|  |    - SKIP / IGNORE Filter: Un-translated graphics kept 100% pristine   |  |
|  +-------------------------------------------------------------------------+  |
|         |                                                                     |
|         v                                                                     |
|  [Translated Pixel-Perfect Game Image]                                        |
+-------------------------------------------------------------------------------+
```

### 1. Pixel-Level Adaptive Color Sampling (`auto_detect_box_colors`)
แทนที่จะพึ่งพาค่าสีขาว `#FFFFFF` แบบ Hardcoded ระบบจะวิเคราะห์สีจากภาพจริงในระดับพิกเซล:
- **Perimeter Pixel Sampling:** สุ่มตัวอย่างสีรอบนอกกรอบข้อความจริง (จุดรอบนอกพิกัด `(x, y, w, h)`) เพื่อหา "สีพื้นหลังที่แท้จริง (True Background Color)"
- **Luminance Contrast Mapping:** คำนวณค่าความสว่างของพื้นหลัง (`bg_lum = 0.299*R + 0.587*G + 0.114*B`):
  - หาก `bg_lum < 115` (พื้นหลังมืด/ดำ เช่น Tutorial, Dark UI): ปรับสีกล่องลบเป็นสีดำตามเนื้อภาพจริง (`#000000`), ปรับสีตัวอักษรเป็นสีขาวบริสุทธิ์ (`#FFFFFF`), และเพิ่มขอบ Stroke สีดำเพื่อความคมชัด
  - หาก `bg_lum >= 115` (พื้นหลังสว่าง เช่น กล่องแชตสีขาว/เทาอ่อน): ใช้สีพื้นหลังตามเนื้อกล่อง (`#F7F7F7` หรือขาว) และใช้ตัวหนังสือสีเทาเข้ม (`#333333`)
- **Alpha Transparency Support:** หากพิกเซลรอบนอกมีค่า Alpha โปร่งใส (`avg_a < 30`) หรือระบุ `transparent`: ระบบจะใช้การเคลียร์ Alpha Channel (`(0, 0, 0, 0)`) แทนการเทสีทึบ ป้องกันภาพ Sprite หรือ UI ลอยตัวไม่ให้เกิดขอบทึบ

### 2. Zero-Leak Pre-render Cleaning (`erase_pad = 3`)
กำจัดเศษตัวหนังสือภาษาอังกฤษเดิมที่แลบออกมารอบขอบอย่างถาวร:
- ยกเลิกการบีบขอบ `[x+6, y+6, x+w-4, y+h-4]` โดยสิ้นเชิง
- ประยุกต์ใช้ระยะปลอดภัยขยายออกนอกกรอบ 3 พิกเซล:
  ```python
  erase_box = [
      max(0, x - 3),
      max(0, y - 3),
      min(im.width, x + w + 3),
      min(im.height, y + h + 3)
  ]
  ```
- รับประกันว่าเส้นโค้ง หางอักษร และสัญลักษณ์รอบนอกจะถูกลบเกลี้ยง 100% ก่อนเริ่มวาดตัวอักษรไทย

### 3. Adaptive Dynamic Typography (`fit_thai_text_to_box`)
ขจัดปัญหาข้อความทะลักล้นกล่องหรือทับ UI อื่น:
- ฟังก์ชันจะจำลองการตัดคำภาษาไทย (`wrap_thai_text_by_pixel`) และวัดขนาดความสูงจริง (`total_text_h = len(lines) * line_height`) เทียบกับความสูงของกล่อง (`avail_h = h - padding_y`)
- หากข้อความยาวเกินความสูงหรือความกว้างของกล่อง ระบบจะวนลูปปรับลดขนาดฟอนต์ลงทีละ 1 พอยต์ (จาก `desired_size` ลงมาจนถึงขนาดต่ำสุดที่เหมาะสม เช่น 10-12pt)
- ข้อความภาษาไทยจึงถูกจัดวางให้อยู่ภายในกรอบเดิมเสมอ โดยไม่ทะลักไปทับกล่องแชตอื่นหรือปุ่มกดของเกม

### 4. Ground Truth Geometry Specification & Photoshop Coexistence Model
- **Ground Truth Catalog Calibration:** บันทึกพิกัดจริงที่วัดจากงานศิลป์ของเกมลงใน `get_ground_truth_catalog_entries` และ `image_dialogues.csv`:
  - `MasaruEnding1_Phone`: แก้ไขจาก `X=380, W=200` เป็น `X=412, W=230` ให้ตรงกับจอโทรศัพท์เป๊ะระดับพิกเซล
  - `ShionMessage1`: กำหนดกรอบแชต 3 กล่องที่ `X=412, W=230, Y=150/275/400`
  - `Fishguide`: กำหนดกรอบ 4 ข้อความให้คลุมตั้งแต่ "CLICK", "ROD AND BAIT", "CATCH" ครบทุกจุด
  - `BeachBarTutorial`: ขยายกรอบคลุมตัวเลข "1.", "2.", "3.", "4." ทุกจุด
- **Photoshop Coexistence Model:**
  - **Automated Engine (99% ของเกม):** ภาพแชตมือถือ, หน้าจอสอนเล่น (Tutorials), คำบรรยาย UI ทั้งหมด จะถูกเรนเดอร์ผ่าน Engine อัตโนมัติด้วยความเร็วระดับเสี้ยววินาที สวยงาม กลมกลืน โดยไม่ต้องเปิดโปรแกรมแต่งภาพ
  - **Photoshop Dedicated Artwork (1% เท่านั้น):** หากมีภาพที่เป็น Title Screen หรือ Hero Logo ประจำเกมที่ต้องการลายเส้นวิจิตรพิเศษ ผู้ใช้สามารถแต่งด้วย Photoshop ได้ตามอัธยาศัย โดยเพียงนำไฟล์ `.png` มาวางในโฟลเดอร์ `translated/` ระบบจะนำภาพนั้นไปเข้ารหัสเข้าเกมจริงทันที

## Verification & Impact (การตรวจสอบและผลลัพธ์)

1. **Fishguide.png & BeachBarTutorial.png:**
   - กล่องสี่เหลี่ยมสีขาวบนภาพพื้นหลังดำสนิทหายไป 100% กลายเป็นพื้นหลังสีดำเนียนสนิทไปกับเกม
   - ตัวอักษรภาษาไทยเป็นสีขาว คมชัด มี Stroke สีดำรองรับ อ่านง่าย สบายตา
   - ตัวเลขนำหน้า "1.", "2.", "3.", "4." และหัวเรื่อง "CLICK", "ROD AND BAIT", "CATCH" ถูกลบและแทนที่ด้วยภาษาไทยครบถ้วน ไร้เศษตัวอักษรเดิมแลบ

2. **MasaruEnding1_Phone & ShionMessage1:**
   - พิกัดกล่องแชตประกบพอดีกับกรอบโทรศัพท์ (`X=412, Width=230`) ไม่กินเนื้อวอลเปเปอร์ด้านซ้าย และไม่มีเศษจุดไข่ปลา `..` หลุดขอบด้านขวา
   - ฟอนต์ภาษาไทยถูกปรับสเกลอัตโนมัติให้พอดีกับความสูงของแต่ละกล่องแชต (Fit-to-Box) ไม่ทะลักทับกล่องถัดไป
   - ตัวเลขเวลา Timestamp เช่น `21:00`, `19:42` ถูกแยกไปวางที่มุมขวาล่างของกล่องอย่างเป็นระเบียบตาม UI โทรศัพท์จริง
