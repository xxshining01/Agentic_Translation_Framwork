# ADR-001 Why Agentic Architecture instead of One Super AI

Status Proposed
Date 2026-07-09
Decision Maker Product Owner + AI Solution Architect

---

## 1. Context and Problem Statement

ในการแปลโปรเจกต์ซอฟต์แวร์และเกม โมเดลภาษาขนาดใหญ่ (LLMs) ในปัจจุบันมีความสามารถสูง แต่มีจุดอ่อนที่ร้ายแรงคือ Instruction Competition (การแย่งชิงความสำคัญของคำสั่ง) เมื่อเราใช้ AI ตัวเดียว (Monolithic Architecture) ในการรันคำสั่งทั้งหมดผ่าน Master Prompt เดียว โมเดลจะต้องรับภาระทางกระบวนการคิดที่ขัดแย้งกันเองในเวลาเดียวกัน เช่น

 ต้องแปลภาษาให้สละสลวยและเป็นธรรมชาติ
 ต้องรักษาบุคลิกและลักษณะนิสัยของตัวละครให้คงที่
 ต้องตรวจสอบคำศัพท์เฉพาะจาก Glossary
 ต้องรักษาโครงสร้างของไฟล์ต้นฉบับ
 ต้องไม่ยุ่งกับโค้ดหรือ Syntax ของเอนจินเกม (เช่น การกรองคำสั่ง `image` หรือตัวแปรต่างๆ ออกจากข้อความที่ต้องแปล)

เมื่อความซับซ้อนของคำสั่งเพิ่มขึ้น ความน่าจะเป็นที่ AI จะทำตามคำสั่งครบ 100% จะลดลงอย่างมีนัยสำคัญ ผลลัพธ์ที่ตามมาคือ AI เริ่มแปลแท็กโค้ดผิดพลาด ทำโครงสร้างพัง หรือหลุดคาร์แรคเตอร์ตัวละคร

## 2. Decision

เราตัดสินใจใช้ Multi-Agent Architecture (Agentic Workflow) แทนที่การใช้ AI ตัวเดียว

ระบบจะถูกแบ่งแยกหน้าที่อย่างเด็ดขาด (Decoupling) ตามหลักการ Single Responsibility Principle (SRP)

 Semantic AI Agents AI แต่ละตัวจะรับผิดชอบงานทางภาษาเพียง หนึ่งงาน เท่านั้น (เช่น Translator Agent ทำหน้าที่แปลอย่างเดียว, Editor Agent ทำหน้าที่เกลาภาษาอย่างเดียว)
 Deterministic Logic (Python) งานที่ต้องการความแม่นยำ 100% จะถูกยกเลิกจากการเป็นภาระของ AI และส่งให้ Python จัดการแทนทั้งหมด เช่น การใช้ Regex ที่แม่นยำในการแยกแยะและข้ามบรรทัดโค้ดก่อนที่จะส่งข้อความไปให้ AI แปล

## 3. Rationale

 Elimination of Instruction Overload เมื่อ Agent หนึ่งตัวได้รับคำสั่งเพียงข้อเดียว (เช่น ตรวจสอบประโยคนี้ว่าใช้สรรพนามตรงกับ Character Memory หรือไม่) ประสิทธิภาพความแม่นยำของโมเดลจะพุ่งสูงขึ้นเข้าใกล้ขีดสุด
 Strict Boundary Between Code and Text โครงสร้างของไฟล์ (ไม่ว่าจะเป็น Script หรือโครงสร้าง JSON จากการแกะไฟล์เกม) เป็นสิ่งที่เป็น Logic ตายตัว การให้ AI มาตัดสินใจว่าบรรทัดไหนคือโค้ดบรรทัดไหนคือบทสนทนาเป็นการใช้เครื่องมือผิดประเภท การใช้ Python และ Regex จัดการโครงสร้างเหล่านี้ช่วยรับประกันว่า Code Integrity จะไม่ถูกทำลาย
 Localized Error Recovery หากเกิดข้อผิดพลาดในการแปล ระบบสามารถสั่ง Retry เฉพาะ Agent หรือเฉพาะประโยคที่พังได้ทันที โดยไม่ต้องเริ่มต้นกระบวนการแปลใหม่ทั้งหมด ซึ่งช่วยประหยัดทั้งเวลาและ Token

## 4. Consequences

Pros (ข้อดี)

 โครงสร้างเกมและโค้ดจะไม่พังจากการแปลของ AI
 สามารถแยกใช้โมเดลที่แตกต่างกันได้ตามความเหมาะสม (เช่น ใช้โมเดลราคาถูกสำหรับงานตรวจสอบโครงสร้าง และใช้โมเดลตัวท็อปสำหรับงานแปลเชิงอารมณ์)
 ความสามารถในการตรวจจับและแก้ไขข้อผิดพลาด (QA) ทำได้ลึกและแม่นยำขึ้น

Cons (ข้อเสีย)

 ความหน่วง (Latency) ของระบบโดยรวมจะเพิ่มขึ้นจากการเรียก API หลายทอด
 ระบบมีความซับซ้อนในการพัฒนามากขึ้น เนื่องจากต้องสร้าง Event Bus หรือ Workflow Orchestrator เพื่อควบคุมการส่งผ่านข้อมูลระหว่าง Agent
