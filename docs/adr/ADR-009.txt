# ADR-009: KPI Framework for Quality Assurance

**Status:** Proposed
**Date:** 2026-07-09
**Decision Maker:** Product Owner + AI Solution Architect

---

## 1. Context and Problem Statement

ในกระบวนการแปลภาษา คำว่า "แปลดี" เป็นนามธรรม (Subjective) เกินไป หากเราเขียน Prompt ให้ QA Agent ว่า *"จงตรวจสอบว่าแปลดีหรือไม่"* LLM จะทำงานอย่างไร้ทิศทางและมักจะปล่อยผ่านประโยคที่ผิดธรรมชาติ หรือแย่กว่านั้นคือพยายามแก้ประโยคที่ดีอยู่แล้วให้แย่ลง

เพื่อให้ QA Agent สามารถทำงานใน Pipeline (ADR-002) และส่ง Trigger กลับไปยัง Repair Loop (ADR-008) ได้อย่างแม่นยำ เราจำเป็นต้องมีชุดมาตรวัด (Metrics) ที่ชัดเจน เป็นรูปธรรม และสามารถตัดสินเป็นคะแนนหรือสถานะ (Pass/Fail) ได้

## 2. Decision

เราตัดสินใจใช้ **Multi-Dimensional KPI Scoring System** เป็นเกณฑ์มาตรฐานในการตรวจสอบคุณภาพ (Quality Assurance) โดย QA Agent จะต้องประเมินผลลัพธ์ผ่านตัวชี้วัด 4 มิติหลัก ดังนี้:

### 1. Meaning Preservation (การรักษาความหมาย) - น้ำหนัก: สูงสุด (Critical)

* **เกณฑ์:** ข้อความภาษาไทยต้องสื่อความหมายหลัก (Core Message) ของต้นฉบับภาษาต่างประเทศได้ครบถ้วน โดยไม่มีการบิดเบือน ตัดทอน หรือแต่งเติมเนื้อหาเกินความจำเป็น
* **การประเมิน:** Pass / Fail (หากความหมายเพี้ยน QA จะต้องสั่งตีกลับไปยัง Translator Agent)

### 2. Character Consistency & Tone (ความคงเส้นคงวาของตัวละครและน้ำเสียง) - น้ำหนัก: สูง (High)

* **เกณฑ์:** สรรพนามที่ใช้เรียกตัวเอง (First-person pronoun) และสรรพนามเรียกคู่สนทนา (Second-person pronoun) ต้องตรงกับ Character Memory อย่างเคร่งครัด รวมถึงระดับภาษาและความสุภาพต้องสอดคล้องกับอารมณ์ของฉาก
* **การประเมิน:** Pass / Fail (หากหลุดคาร์แรคเตอร์ QA จะสั่งตีกลับไปยัง Editor Agent)

### 3. Contextual Naturalness (ความเป็นธรรมชาติในบริบทภาษาไทย) - น้ำหนัก: ปานกลาง (Medium)

* **เกณฑ์:** รูปประโยคต้องไม่เป็นภาษาแปลกๆ (Translationese) หรือเรียงลำดับไวยากรณ์แบบกำปั้นทุบดิน ต้องอ่านแล้วลื่นไหลเหมือนบริบทการพูดคุยของคนไทยจริงๆ ในสถานการณ์นั้น
* **การประเมิน:** Pass / Warning / Fail

### 4. Formatting & Terminology Compliance (ความถูกต้องของรูปแบบและคำศัพท์) - น้ำหนัก: สูง (High)

* **เกณฑ์:** ต้องใช้คำศัพท์เฉพาะตรงตาม Glossary 100% และจะต้องไม่มีการเผลอแปลแท็กคำสั่ง (เช่น แท็กสีข้อความ หรือตัวแปรชื่อผู้เล่น) แม้ว่า Python จะช่วยดักจับในด่านสุดท้าย (ADR-008) แต่ QA Agent ต้องตรวจทานความสอดคล้องเบื้องต้นด้วย
* **การประเมิน:** Pass / Fail (ตีกลับไปที่ Consistency & Glossary Stage)

## 3. Rationale

การแยกย่อยความรู้สึก "แปลดี" ออกเป็น 4 มิติ ทำให้เราสามารถออกแบบ System Prompt ของ QA Agent ให้เป็นเช็คลิสต์ที่ทำตามได้ง่าย (Rule-based Prompting) เมื่อ AI ตรวจสอบงานเป็นข้อๆ โอกาสที่จะเกิด False Positive (ปล่อยผ่านงานแย่) หรือ False Negative (ตีกลับงานดี) จะลดลงอย่างมีนัยสำคัญ

นอกจากนี้ การระบุหมวดหมู่ความผิดพลาดที่ชัดเจน จะช่วยให้ Repair Loop สามารถสร้าง "Targeted Feedback" เพื่อบอก Agent ตัวก่อนหน้าได้ว่าต้องแก้ไขที่จุดไหน (เช่น "แก้ไขเฉพาะสรรพนาม" หรือ "เรียงรูปประโยคใหม่ให้เป็นธรรมชาติขึ้น")

## 4. Consequences

**Pros (ข้อดี):**

* มาตรฐานการประเมินมีความคงที่ ไม่แกว่งตามอารมณ์ของ LLM ในแต่ละช่วงเวลา
* สามารถนำผลการประเมินมาทำ Dashboard เพื่อดูว่าคอขวดของระบบ (Bottleneck) ไปตกอยู่ที่ Agent ตัวไหนมากที่สุด

**Cons (ข้อเสีย):**

* Prompt ของ QA Agent จะมีความยาวและความซับซ้อนค่อนข้างสูง ส่งผลให้ใชั Token และเวลาประมวลผลต่อประโยคมากกว่า Agent ตัวอื่นๆ
* หากตั้งเกณฑ์เข้มงวดเกินไป อาจเกิดปัญหา Over-correction (แก้แล้วแก้อีกจนระบบติดลูป) จึงต้องใช้ควบคู่กับขีดจำกัดการวนลูป (Max Retries) เสมอ
