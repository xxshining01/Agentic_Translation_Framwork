# ADR-035: Decoupled Glossary-Profile Architecture and Zero-Fallback Invariant

## Status
Approved & Enforced (Architecture Standard)

## Context & Problem Statement
จากการทดสอบใช้งานจริงในโปรเจกต์ `Example RPGM Game` พบปัญหางานแปลล้มเหลวและไม่เสถียรอย่างรุนแรง:
1. **ตัวละครพูดผิดเพศและผิดบทบาทอย่างมีนัยสำคัญ:** ตัวละครหญิง (เช่น `Lucy`) ถูกแปลเป็น "ผม/ครับ", ตัวละครนักเลง (เช่น `Bald Thug`) ใช้สรรพนามสุภาพ "ผม/คุณ/ครับ" กับคนอื่น
2. **สรรพนามแกว่งไปมาไร้เสถียรภาพ:** ตัวละครเดียวกันเรียกคู่สนทนาเปลี่ยนไปมาระหว่าง คุณ/นาย/แก/เธอ
3. **สำนวนการแปลไม่คงที่ (Style & Length Drift):** บางช่วงพยายามแปลแบบตัดทอนคำเพื่อเน้นไว แต่บางช่วงดันแปลยืดยาวยัดทุกคำ
4. **สาเหตุรากเหง้าเชิงสถาปัตยกรรม (Root Cause):**
   - **Boundary Pollution (ความสับสนระหว่าง Glossary กับ Profile):** ระบบเดิมไม่ได้แยกหน้าที่ระหว่าง Glossary กับ Profile ทำให้พยายามสร้างไฟล์โปรไฟล์ให้กับรายชื่อทั้งหมด 445 ตัวในเกม (รวมถึงตัวประกอบที่มีบทพูดแค่ 4 บรรทัดอย่าง Lucy)
   - **The Default Polite Male Catastrophe:** โค้ดของ Consensus Engine (`tlas_consensus_engine.py`) มีตรรกะ Fallback ที่เป็นพิษ: เมื่อตัวละครไม่มีการสกัดนิสัย (เนื่องจากเป็นตัวประกอบที่ถูก Analyzer ข้าม) ระบบกลับยัดเยียดค่า Default ให้กลายเป็น "ชายสุภาพพูด ผม/คุณ/ครับ (Level 4)" บันทึกลงดิสก์
   - **Poisoned Context Ingestion:** เมื่อ Runner แปลบทสนทนา ระบบไปสแกนเจอโปรไฟล์ปลอมเหล่านี้ จึงดึงค่า "ผม/ครับ" ไปบังคับให้ LLM แปลตามอย่างเคร่งครัด
   - **Disappearing System Instruction:** Runner ส่ง Master Instruction เฉพาะข้อความแรก แต่ใน Follow-up Prompts ไม่ได้ส่ง ทำให้โมเดลเกิด Attention Decay ลืมกฎความยาวของกล่องข้อความเกม

---

## Architectural Decisions & Invariants

### 1. Strict Layer Separation: Master Glossary vs. Character Profiles
กำหนดให้แยกหน้าที่และความรับผิดชอบของสองฐานข้อมูลนี้ออกจากกันโดยเด็ดขาด (Separation of Concerns):

```
┌────────────────────────────────────────────────────────────────────────┐
│ Layer 1: Master Glossary (tlas_glossary.json)                           │
│ - บรรจุ Speaker Tags ทั้งหมด 100% ที่ปรากฏในเกม (เช่น 200 - 450 ชื่อ)      │
│ - วัตถุประสงค์เดียว: ล็อกคำแปลชื่อเฉพาะ 1:1 ป้องกันการแปลชื่อเพี้ยนหรือทับศัพท์ผิด │
└────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼ [Target Qualification Filter]
┌────────────────────────────────────────────────────────────────────────┐
│ Layer 2: Character Profiles (data/tlas/profiles/<Name>.json)           │
│ - บรรจุเฉพาะ "ตัวละครสำคัญแท้จริง" (Core/Main Cast ประมาณ 30 - 50 ตัว) │
│ - มีบทบาทขับเคลื่อนเนื้อเรื่อง, มีบทสนทนาต่อเนื่อง, และมีปฏิสัมพันธ์หลายคู่   │
│ - ตัวประกอบ / Ambient NPCs (เช่น Lucy, Thug, Hooker) ห้ามมีไฟล์ Profile  │
└────────────────────────────────────────────────────────────────────────┘
```

### 2. Zero-Profile & Clean Passthrough Invariant (กฎห้ามสร้างโปรไฟล์ตัวประกอบ)
- **[INVARIANT_ZERO_AMBIENT_PROFILE]**: ตัวละครที่จัดเป็น `role_category: "Ambient"` หรือมีบทบาทน้อยกว่าเกณฑ์ จะ **ต้องไม่มีไฟล์ใน `data/tlas/profiles/` เด็ดขาด**
- **Clean Passthrough Runtime:** ในขั้นตอนการแปล หากตัวละครใดไม่มี Profile ระบบจะส่งเฉพาะ **"ชื่อที่ล็อกตาม Glossary"** และปล่อยให้ AI แปลน้ำเสียงและสรรพนามไปตามบริบทของฉาก (Scene Context & Emotion) ตามธรรมชาติ ห้ามสร้าง Profile กลวงไปหลอก AI

### 3. Absolute Elimination of "Default Polite Male" Trap
- **[INVARIANT_NO_POLITE_MALE_FALLBACK]**: ห้ามเขียนโค้ดที่ Fallback ตัวละครที่ไม่ทราบเพศหรือไม่มี Tag นิสัยให้กลายเป็น "ชายสุภาพ (ผม/คุณ/ครับ)" โดยเด็ดขาด
- หากตัวละครสำคัญใดไม่ทราบเพศแน่ชัด ให้ใช้ Neutral Speech Register (`ฉัน / เธอ / นาย`) ไร้หางเสียง "ครับ" หรือ "ค่ะ" จนกว่าจะมีหลักฐานยืนยันจากเนื้อเรื่อง
- ตัวละครที่เป็นนักเลง (Thug, Ruffian, Gang, Punk) ต้องได้รับการกำหนดโทนหยาบ/กระด้าง (`ข้า/เอ็ง`, `กู/มึง`, `ฉัน/แก` ลงท้าย `วะ/เว้ย`) ห้ามปล่อยให้หลุดเป็น "ครับ"

### 4. Persistent Invariant Prompting (ป้องกันคำสั่งล่องหน)
- **[INVARIANT_PERSISTENT_PROMPTING]**: ในระบบแปลหลายรอบ (Multi-turn Runner):
  - ห้ามพึ่งพา System Prompt ในอดีตเพียงอย่างเดียว
  - ทุกๆ พร็อมพ์ (รวมถึง Follow-up Prompts #2, #3, #4...) จะต้องมี **Mini-System Invariant** แนบไปกับข้อความของผู้ใช้เสมอ เพื่อคุมความยาวบรรทัด (~40-48 ตัวอักษร), ห้ามตัดทอนคำ, ห้ามขยายความยืดยาว, และคงสภาพ Tag 100%

### 5. Speaker Forward-Propagation (ป้องกันประโยคตาบอด)
- **[INVARIANT_SPEAKER_PROPAGATION]**: ข้อความที่พูดต่อเนื่องกันใน Scene หรือ Event เดียวกัน หากบรรทัดถัดไปมี `speaker == ""` ให้ทำการคัดลอก (Forward-Fill) ชื่อผู้พูดจากบรรทัดก่อนหน้า เพื่อให้ระบบสแกน Glossary และ Context ได้ครบถ้วนทุกบรรทัด

## Consequences & Expected Impact
1. **กวาดล้างไฟล์โปรไฟล์ขยะ:** ลดจำนวนไฟล์ใน `data/tlas/profiles/` จาก 445 ไฟล์ เหลือเฉพาะตัวละครสำคัญ 30-50 ตัวที่สะอาดและมีข้อมูลจริง 100%
2. **กำจัดปัญหาตัวละครพูดผิดเพศ:** ตัวประกอบหญิง (เช่น Lucy) จะไม่ถูกสั่งให้พูด "ผม/ครับ" อีกต่อไป และนักเลงจะไม่พูดสุภาพระดับ 4
3. **ความเสถียรของงานแปล:** การส่ง Mini-System Invariant กำกับทุกข้อความจะทำให้ระดับความสั้นยาว ลีลาภาษา และความต่อเนื่องคงที่ ไม่เปลี่ยนไปมาตามขนาดของ Batch หรือลำดับของแชต
