# ADR-003: Agent Responsibility Matrix

**Status:** Proposed
**Date:** 2026-07-09
**Decision Maker:** Product Owner + AI Solution Architect

---

## 1. Context and Problem Statement

จาก ADR-002 ที่เรากำหนด Workflow ไว้ หากไม่มีการระบุขอบเขตความรับผิดชอบของแต่ละส่วนประกอบให้ชัดเจน จะเกิดปัญหา "Agent ล้ำเส้นหน้าที่" เช่น Translator พยายามเกลาคำให้สวยจนความหมายเพี้ยน หรือ Editor พยายามไปยุ่งกับสัญลักษณ์โครงสร้างไฟล์ การไม่กำหนดขอบเขตที่ชัดเจนจะทำให้ Prompt บวมและควบคุมคุณภาพได้ยาก

## 2. Decision

ระบบจะแบ่งขอบเขตความรับผิดชอบออกเป็น 2 เสาหลัก คือ **AI Agents (Semantic)** และ **Python Modules (Deterministic)** อย่างเด็ดขาด ดังนี้:

### AI Agents (Semantic Processing)

มีหน้าที่จัดการงานที่ต้องใช้ความเข้าใจทางภาษาและบริบท

1. **Translator Agent:**
* **หน้าที่:** แปลความหมายจากภาษาต้นทางเป็นภาษาเป้าหมายให้ถูกต้องและครบถ้วนที่สุด
* **ข้อห้าม (Constraints):** ห้ามดัดแปลงความหมาย ห้ามตัดทอนเนื้อหา และยังไม่ต้องสนใจความสละสลวยมากเกินไปจนเสียความหมายเดิม


2. **Editor Agent (Persona & Emotion):**
* **หน้าที่:** เกลาประโยคที่แปลมาแล้วให้เป็นธรรมชาติ ปรับน้ำเสียง (Tone) และระดับภาษาให้ตรงกับลักษณะนิสัย (Character Memory) และอารมณ์ของฉาก
* **ข้อห้าม (Constraints):** ห้ามเปลี่ยนความหมายหลัก (Core Meaning) ที่ Translator ทำมา


3. **QA Agent:**
* **หน้าที่:** ประเมินคุณภาพข้อความตามตัวชี้วัด (KPIs) เช่น ความเป็นธรรมชาติ ความถูกต้องของบริบท และส่งคืน (Reject/Retry) หากไม่ผ่านเกณฑ์
* **ข้อห้าม (Constraints):** ห้ามแก้ไขข้อความด้วยตัวเองเด็ดขาด ต้องชี้จุดผิดแล้วส่งให้ Editor หรือ Translator เป็นผู้แก้


4. **Timing Agent:**
* **หน้าที่:** ประเมินจังหวะการเล่าเรื่องและแทรกสัญลักษณ์ Narrative Pacing (เช่น `✎`, `|`, `.` หรือ tag จังหวะหยุด) ตามอารมณ์ของบทสนทนา
* **ข้อห้าม (Constraints):** ห้ามแก้ไขคำศัพท์หรือไวยากรณ์ในประโยค



### Python Modules (Deterministic Logic)

มีหน้าที่จัดการข้อมูล Logic โครงสร้าง และงานประมวลผลปริมาณมาก (Large-scale Data Mapping)

1. **Parser & Regex Engine:**
* **หน้าที่:** ดึงข้อความออกมาจากไฟล์เอนจินเกม (เช่น โครงสร้าง Godot หรือ Ren'Py) และใช้ Regex กรองคำสั่งที่ไม่ใช่บทสนทนาออกอย่างแม่นยำ (เช่น ป้องกันคำสั่ง `image` หรือ tag โค้ดถูกส่งไปเป็น Text ให้ AI แปล)


2. **Context & Assembly Manager:**
* **หน้าที่:** รวบรวมข้อมูล จัดการ Data Mapping และประกอบ Translation Memory (TM) รวมถึง Glossary ตามบริบท ก่อนส่งเป็น Prompt ให้ระบบ AI


3. **Syntax Validator:**
* **หน้าที่:** ตรวจสอบความสมบูรณ์ขั้นสุดท้าย เช่น ตัวแปรในรูปประโยค (Variables) อยู่ครบตำแหน่งหรือไม่ หรือ AI มีการเผลอแปลแท็กคำสั่งหรือไม่



## 3. Rationale

การกำหนดหน้าที่ตายตัวเช่นนี้ทำให้เราสามารถออกแบบ System Prompt สำหรับ AI แต่ละตัวได้สั้น กระชับ และตรงจุดที่สุด นอกจากนี้ การใช้ Python รับผิดชอบฝั่ง Deterministic อย่างเต็มตัว (โดยเฉพาะการใช้ Regex จัดการโครงสร้างเอนจินและคำสั่งภาพ) จะช่วยปิดประตูความเสี่ยงที่ AI จะไปทำลายโครงสร้างไฟล์โค้ดของเกมได้อย่างสมบูรณ์

## 4. Consequences

**Pros (ข้อดี):**

* ควบคุมคุณภาพง่ายและตรงจุด (เช่น ถ้าอารมณ์ตัวละครไม่ตรง ไปแก้ Prompt ที่ Editor ตัวเดียว ไม่กระทบส่วนอื่น)
* ระบบมีความเสถียรสูง เพราะงานตรวจสอบโค้ดถูกจัดการด้วย Logic ทางคณิตศาสตร์ของ Python ไม่ใช่ความน่าจะเป็นของ AI

**Cons (ข้อเสีย):**

* การสร้างโครงสร้าง Data Mapping ในฝั่ง Python เพื่อสื่อสารระหว่าง Agent ต้องทำอย่างรัดกุมและแม่นยำมาก

## [UPDATE: 2026-07-18] Context-Aware Agent Boundaries
**Rationale for Update:**
แม้ว่าเราจะแบ่งหน้าที่ระหว่าง Semantic และ Deterministic อย่างชัดเจนแล้ว แต่พบว่าผลลัพธ์การแปลบางส่วนยังขาดความเป็นธรรมชาติหาก Agent ไม่ทราบ "ประเภทของข้อความ" (Role) ดังนั้น เราจึงอนุญาตให้ Translator Agent รับรู้ถึง `Role` (เช่น Dialogue/Story, Item, System) เพื่อให้ AI สามารถพิจารณาบริบทได้อย่างลึกซึ้ง (Context-aware) หากเป็นบทสนทนา หรือแปลตรงตัวหากเป็นข้อความระบบ โดยไม่ถือว่าเป็นการล้ำเส้นหน้าที่ แต่เป็นการเพิ่มบริบทเพื่อให้การตัดสินใจแม่นยำขึ้น
