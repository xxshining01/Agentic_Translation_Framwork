# SDD-002: Context Engine and Dynamic Prompt Assembly

**Project:** Agentic Translation Framework (ATF)
**Phase:** 3 - Software Design Document
**Status:** Draft

---

## 1. Overview

Context Engine คือโมดูลฝั่ง Python ที่ทำหน้าที่รับ TranslationToken (จาก SDD-001) ที่มีสถานะ PENDING มาทำการ "เติมข้อมูลบริบท (Context)" ให้เต็ม ก่อนที่จะส่งให้ AI Agent ทำงาน ระบบนี้เปรียบเสมือนผู้ช่วยที่วิ่งไปหาข้อมูลจาก Database (Character, Glossary, TM) มาป้อนให้ AI

## 2. Retrieval Algorithms (อัลกอริทึมการสืบค้นข้อมูล)

เพื่อไม่ให้ระบบทำงานช้า (Performance Bottleneck) เราจะใช้อัลกอริทึมเฉพาะทางในการค้นหาข้อมูลแต่ละประเภท:

### 2.1 Glossary Matching (การค้นหาคำศัพท์เฉพาะ)

* **ปัญหา:** หากมีคำศัพท์ใน Glossary 5,000 คำ การใช้ Regex วนลูปเช็คทีละคำกับทุกประโยคจะกิน CPU มหาศาล

* **อัลกอริทึม:** ใช้ Aho-Corasick Algorithm (ผ่านไลบรารี ahocorasick ใน Python)

* **การทำงาน:**
    1. โหลด Glossary ทั้งหมดสร้างเป็น Automaton Tree ไว้ใน Memory ตอนเริ่มโปรแกรม
    2. เมื่อประโยค original_text เข้ามา จะสแกนผ่าน Tree นี้เพียงรอบเดียว (O(n) time complexity) เพื่อกวาดคำศัพท์ทั้งหมดที่เจอ
    3. นำคำที่เจอและคำแปลบังคับ ยัดลงใน context.glossary_matches

### 2.2 Character Profiling (การดึงข้อมูลตัวละคร)

* **อัลกอริทึม:** Hash Map Lookup (Key-Value)

* **การทำงาน:** ใช้ฟิลด์ speaker จาก Token เป็น Key ไปดึงลักษณะนิสัย (Traits), สรรพนาม (Pronouns) จาก Character DB มาใส่ใน context.character_traits

### 2.3 Translation Memory - TM (การค้นหาประวัติการแปล)

* **อัลกอริทึม:**
    1. Exact Match (O(1)): เช็คก่อนว่าประโยคนี้เคยแปลไปหรือยัง ถ้าเคยแปลและยืนยันแล้ว จะข้าม AI Translator ไปเลย
    2. Fuzzy Search / Vector Similarity (Optional): หากไม่เจอ Exact Match จะใช้ TF-IDF หรือ Vector Embeddings (เช่น ChromaDB) หาประโยคที่มีความคล้ายคลึงเกิน 80% มาเป็น Reference ให้ AI

### 2.4 Story Summarization (การสรุปเนื้อเรื่อง)

* **อัลกอริทึม:** LLM Summarization
* **การทำงาน:** ใช้ `SummarizerAgent` นำประวัติการแปลล่าสุด (เช่น 50-100 ประโยค) มาทำการสรุปเนื้อเรื่อง (Pre-processing) ก่อนเริ่ม Pipeline หลัก แล้วนำผลลัพธ์ไปใส่ใน `context.story_summary` ให้ Agent ตัวอื่นได้เห็นภาพรวมของเหตุการณ์

## 3. Prompt Assembly (การประกอบร่าง Prompt)

เราจะใช้ Jinja2 Template ในฝั่ง Python เพื่อนำ Context ที่หามาได้ ประกอบเข้ากับ System Prompt หลักของแต่ละ Agent (ตัวอย่างด้านล่างคือของ Translator Agent)

### 3.1 Jinja2 Prompt Template (Pseudo-code)

```
# System Message Template สำหรับ Translator Agent
You are an expert translator specializing in game localization (English to Thai).
Your task is to translate the given dialogue accurately.

{% if context.character_traits %}
[Character Info]
Speaker: {{ speaker }}
Traits: {{ context.character_traits | join(', ') }}
{% endif %}

{% if context.glossary_matches %}
[Mandatory Glossary]
You MUST use these exact translations:
{% for en_term, th_term in context.glossary_matches.items() %}
- {{ en_term }} -> {{ th_term }}
{% endfor %}
{% endif %}

{% if context.translation_memory %}
[Reference Memory]
Similar translated lines:
{% for mem in context.translation_memory %}
- EN: {{ mem.en }} | TH: {{ mem.th }}
{% endfor %}
{% endif %}

# Task
Translate the following text. Preserve the core meaning. Do not add narrative elements.
Original Text: {{ original_text }}
```

## 4. Output to Agent Swarm

เมื่อ Python ประกอบ Prompt เสร็จ (ผ่านคำสั่ง template.render(...)) จะทำการห่อข้อความส่งผ่าน LLM API (เช่น OpenAI หรือ LiteLLM) ในรูปแบบของ Chat Completion Array:
```
[
  { "role": "system", "content": "<ผลลัพธ์ที่ได้จาก Jinja2 Template ด้านบน>" },
  { "role": "user", "content": "Start translation." }
]
```

ผลลัพธ์ที่ตอบกลับมาจาก API จะถูกนำไปอัปเดตลงในช่อง outputs.translator_output ของ TranslationToken ต่อไป
